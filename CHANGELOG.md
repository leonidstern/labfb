# Changelog

Versions follow [semver](https://semver.org). Before 1.0, a minor version can change how things work.

## Unreleased

- Board mode on request (experiment `board`): ⇧B or ⋯ > "open as board" opens the page you are on as a board named after it (saved on its first change). On a board, ⇧B, "back to page" or Esc on an empty board returns to the page, scrolled where you were. ⌘K lists boards: name, frames, when saved.
- On the board page a click selects a frame, Enter or a second tap enters it (it gets the pointer and the focus), Esc leaves it and then clears the selection; Tab and ⇧Tab step through the frames, ⇧0 fits the selected one, + and - zoom, the camera is kept in the page's address, and a title card says when its page was edited. On a phone a plain "done" leaves a frame.
- The board page (experiment `board`): `/_lab/board/<name>` shows a board's frames on one canvas. Pan with the wheel, two fingers or a drag; zoom with Ctrl/⌘ + wheel or a pinch; ⇧1 fits everything, ⇧2 is 100%. Frames are the lab's pages, 8 alive at once (3 on a phone), the rest plain title cards (label, path, size). The board never reloads when a page is saved. Selecting, entering a frame, and comments on a board come later.
- Boards, MCP and skill (experiment `board`): the MCP tool `board` (action new, add, move, pick or list; the same arguments as the command) is listed, with one sentence in the server's instructions, only where labit.json turns `board` on, so sessions without boards carry no extra tool text. The skill gets a short section: options as variants (three unless asked, each different in one way, edit the copied files, never write the page out again), widths, flows, the lab places frames, a pin on a frame changes that frame only, "Picked b" is put into the real page.
- Boards, what an agent reads and picking (experiment `board`): a board's agent text (`/_lab/agent/_board/<name>`) lists its frames in order, then its pins; a pin on a variant carries one line, `frame: b of board pricing-hero (variant of /pricing, 1280×800, "price first", beside a, c)`; a pin on the board itself (anchor `board`, signed px from the nearest frame) reads `on: the board, not a page` and `near: frame b …`; a pin made on a page inside a frame says `seen on: board …, frame …`. The frames are said once per session and again only when they change. `labit board pick <board> <frame>` marks that frame picked, archives the others (files kept) and arrives in the next wait as a pin from the person, with what to do (`Put b's change into pricing.html, then reply --done`); several frames named keep them all and mark none. A wait on a board, or on the page it is about, hears that board's pins and its variants'.
- Boards, commands (experiment `board`): `labit board new "<topic>" --of /page --variants 3` copies a plain HTML page into `.lab/boards/<board>/a.html`, `b.html`, `c.html` (up to 6; the page's folder as `<base>`, so its styles and pictures still load) and prints the link; `--widths 390,820,1280` and `--flow /a,/b,/c` show the real pages and copy nothing. `board add` (a frame, a page, or an .html file to copy in; label, width, `--after`), `board move` (`--after` or `--first`) and `board list` follow. The lab places frames; the agent gives an order only. Behind a dev server a variant is not copied yet: the command says to use `--widths` or `--flow`. With the flag off the command says how to turn boards on.
- Boards, data layer (experiment `board`, off by default): a board is `.lab/boards/<name>.json`, frames that are lab pages at a device size. `GET /_lab/api/board?name=` (or `?page=/x`, the board of that page) returns it with every frame placed by the lab; `PUT` saves it (this computer only; a stale `rev` gets 409, a frame is archived, never dropped). A variant file in `.lab/boards/<name>/<frame>.html` is served at `/_lab/board/<name>/<frame>` with the widget, and the lab watches `.lab/boards` itself, also behind a dev server: a saved variant updates only its own frame, a changed board file counts in `boards` in the live state, and no page reloads. A page loaded into a frame is not marked as opened. With the flag off none of this exists.
- A page behind a dev server can sit in a frame: the lab drops the dev server's `x-frame-options` on pages (it already dropped the content security policy). Other files keep their headers.
- Shift and a digit (⇧1, ⇧2, ⇧0), ⇧D, ⇧M and the like no longer work the comment, done and hide keys: Shift is left free for the board. A plain 1, D and M are as they were. An Escape that closes a comment box or the chat now says it was used.
- A page inside a board's frame (named `lab:<id>`, with a board on top) draws nothing and binds nothing: no bar, pill, pins or menu, no key handler of the widget's. It still follows saves in place, reading the board's stream instead of opening its own, and passes the keys it hears to the board. Nothing changes for any other page; the board itself comes later.
- Two frames of one page (the board's) no longer swap their scroll when a save reloads both: the position kept across a reload is stored per frame name, not per page. A page not in a frame keeps its key.
- A board page (a page whose key is `/_board/<name>`) never reloads or patches itself on a save of a file: its frames follow saves, the board does not. It still reloads for a new widget script and follows the comments. Other pages are as before.
- Phones: a comment made by holding the page always gets the cursor and the keyboard. The box used to focus itself during the hold, which Safari could do without a keyboard; now the finger's lift focuses it, once.
- Phones: a pinch zoom no longer breaks the widget. While zoomed, the bar, the chat, the list and a thread's or new comment's sheet stay on screen at their usual size; pins stay on the page and zoom with it.
- Pause sits beside what moves, not in the bar: each video and each animated element on the page gets a small pause / play just past its top right corner, over the page (nothing shifts), that stops or starts only that one. It shows with the comments and hides with them (M). **P** still pauses everything, or plays what was paused. The bar's pause button is gone.
- A pin handed to a wait that gets no reply of any kind (on it, progress, a question, an answer) within 2 minutes counts as not answered: it goes to the next wait, any session's, and its card says "not answered". The pill says "Claude isn't answering" instead of "talking to Claude" until that session replies to anything, and a session that isn't answering no longer ends another session's wait. `LAB_ANSWER_MS` sets the time. Before, a shell loop left running by a closed session kept waiting: pins went to it and sat unanswered. The skill, `labit --help` and the README say never to wrap `wait` in a shell loop.
- Lighter page script (−1.6 KB gzipped, 59.2 → 57.6 KB): the `?kbdebug` phone logger no longer ships, and a few unused pieces are gone (the chat's never-used "reply to a message" path, the hidden prev/next new-comment buttons, helpers nothing called, two comment-box options nobody set, the second copy of the labit mark, a long licence banner). Nothing changes on a page.
- Comment boxes share one observer of the page. Each redraw built a new box with an observer of its own that stayed for good, so with a thread open the observers piled up and every change to the page ran all of them.
- The npm package is 122 KB packed, down from 133: the command line is one minified file (`dist/local.mjs`), and `dist/` is cleaned before each build, so chunks from an older build no longer ship. Nothing changes in how labit runs. A dead second copy of the `publish` code is gone.
- A long comment's scrollbar sits at the box's right edge. With your name already set the box keeps one row (text, name, arrow); once the words scroll, the name and arrow drop to a row of their own so the scrollbar is no longer left of them.
- Holding Shift over words (to quote them) shows the drawn I-beam with a low ink band at its foot, in place of the I-beam with a green pin tip.
- One key for the mode: `1` (or a click on the switch) toggles between comment and pointer: once for the pointer, again for the comment. The switch reads "(1)" and the hint "1 comment / pointer". Key `3` and the `pointer` shortcut are gone; a `pointer` key left in a settings file is ignored without a message.
- The listening pill drops the session name: "talking to Claude · Opus 5.5", not "… (labit for writing)". The name is in the pill's tooltip, and still in the labs & pages list.
- On computers a comment on a spot or an area is one card like the dialog on words: the page's colour, the card's shadow, and the box (and its actions row, where there is one) 8 px in, its corners concentric with the card's.
- The listening mark's colours: green while an agent listens or works, amber while the page reconnects to the lab (it was faded green), muted grey when no agent listens (it was black). Its tooltip names the state first (Listening, Working, Away), then the resume command.
- Done pins are as big as open ones, only faded (50%). Before, a done pin also shrank to 80% (64% on phones); a pin whose spot is gone still does.
- While a new comment is open the page shows its own pointer, empty or not (it used to switch only once you typed, so an empty box still showed the pin cursor).
- Agents read a pin's or chat message's whole thread before answering, and don't guess from the page, URL or #section what it asks (`wait`, the plugin's wake turn and the skill say so).
- Removed the parked list window and draft mode (both were off): their code, styles and the held-draft pins. The bar's New pill, J/K and show/hide done work as before.
- What `wait` hands an agent (and the skill) now says: work that takes more than a minute (a build, a restart, a PR) gets `reply <id> --on-it` on each pin first, then the work. A batch worked through without a word looked lost: picked up, then nothing for 13 minutes.
- Two sessions waiting on the same pages are told: the one whose wait the other ended reads that it should leave those pages to that session, and the newcomer's first pins come with a heads-up naming the other. Before, they took turns ending each other's wait in silence, and a pin could go to the one about to stop.
- A lab nobody uses parks itself after an hour: no page open on it, no agent waiting or working on its pins. Start it again from the switcher (⌘K) in another lab, or run labit in its folder. `LABIT_IDLE_MS` sets the time; 0 keeps a lab running. Started again, it hears the session that listened last: that session's labit plugin wakes it for the next pin, from any folder.
- A click outside an open comment closes it even with text typed in it; the words stay as a draft (Escape still discards them). Before, the box held on to the click and couldn't be closed that way.
- The npm package no longer carries CHANGELOG.md (−28 KB packed); the changelog lives on GitHub and in each release's notes.
- Pause: a page with video or animation gets a **pause** button in the bar (key **P**, changeable as `pause` in `shortcuts`). Paused, the page's videos and animations stand still (the widget's own keep moving) and the button says **play**. A comment written while paused carries `paused` in its anchor, and the agent reads "page paused: …" with the video's second.
- The go action is just another comment: it sends a comment that says "go" on the words or the spot, and the pin looks like any other (your initial, the ring while the agent works, the tick when done). The separate go pin design (a green "go" face) is gone.
- `labit reply <id> "question" --choice "A" --choice "B" [--recommend B]` (also the MCP `reply` tool's `choices` and `recommend`): the agent asks with 2 to 6 choices and its own pick. The thread card shows the question with no bubble, then the versions as a plain list (a tick on the one picked, the agent's own at first; no letters, no tags), then one Keep, always there and always reading Keep, which sends the pick; it comes back in the next `wait` as `Picked B: …` with the question's id. No keys on the card: tap, Keep; Esc closes. On phones the question is a half-height sheet with 44 pt rows. Version stays 2: `choices` and `recommend` (the agent's) and `picked` (the person's) are only added fields, and an older lab or widget shows them as plain messages.
- Selecting words opens the comment dialog at once (computers): no actions bar first, the cursor in its box. Every action in its row sends at once on a click: `rewrite` sends `Rewrite: “…”` (no more box to edit; the agent proposes the wording), `cut`, `go` and your own as before; the `ask` option of an action is gone. The regular dialog on a spot or an area has the same row, from the `actions.spot` setting (default `go`, `remove`, `fix`; `remove` sends `Remove this`, `fix` sends `Fix this`). Phones keep their bar. Action keys: ⌥ + 1 to 4 run the dialog's buttons in order (holding ⌥ shows the numbers); the slash keys (`/c` + Enter …) and the "/ for actions" hint are gone.
- A plain click on text is a point pin, never a quote of the word under it (it used to be saved as text with that word and highlight it); only a Shift-drag quotes words.
- Never stuck: a pin tells you it is moving. `labit reply <id> --progress "…"` (CLI and MCP `reply` with `progress`) keeps one short line on the thread, the latest only, with its time: no message bubble, nothing marked done; an answer, a new message or resolving clears it. While an agent works, the connection pill reads "Claude · <line> · 40 s ago" in a box of one width, so nothing beside it moves; phones have no pill, so the line heads the open thread's sheet. Hovering a working pin's ring shows the same line.
- Never stuck: the queue. The pill adds "· 2 waiting" for pins handed to the agent but not answered; a waiting pin's thread says "waiting · 1st in line" in its stamp row; the list shows the pins being worked on first, then those waiting in order.
- Never stuck: the ring is the state. Sent: none. Picked up (handed over, nothing from the agent yet): a still pale green ring. Working (`--on-it` or a progress line): the turning green ring. Waiting in line: a still muted ring. No sign for 5 minutes: a still grey ring, and the pill says "no update for 6 min · last: …". The agent's question (`--question`): an amber ring. Done: none, the ✓ face as before. They crossfade over 300 ms. The thread's stamp shows the turning ring only while the agent works (picked up is the ✓✓ again).
- Never stuck: the reminder an agent gets for a handed pin with no answer after 3 minutes now also covers one it said it is on (`--on-it`, or a progress line) and has shown no sign of since; each line says how long and its last progress line.
- The skill and README tell agents to use `--progress` during long work.
- Agent pins are in: a pin the agent left always wears labit's mark in place of a letter, with no flag. The `agentPins` and `liveUrl` flags are gone (liveUrl had no feature behind it yet).
- The ⋯ menu no longer has a **trying** section of flag switches. Flags are set only in `labit.json` (`"flags": { "<flag>": true }`) or your own settings file, read when the lab starts; the lab's `POST /_lab/flags` is gone.
- Quoting words: a drag that starts or ends inside a word takes the whole word, so a note is on "Send … carry", not "nd … ca". A drag that stays inside one word keeps exactly its letters.
- Pins move less: hover 1.03, no movement on press, and the open pin gets only its green edge (no lift), so clicking away doesn't shift it. The send and bar buttons don't move on press.
- A pin stays the same element across redraws: clicking it, closing it, pointing away or clicking the page no longer restarts its ring, pop or face change. Reading a new reply no longer plays the face change, and the change is quieter.
- A reply in a thread the agent already has comes with its thread (`wait`, CLI and MCP): the opening comment with its spot, then every message in order with name, time and state (on it / done / question), the new ones marked `← new`. A long thread shows the opening comment and its last 8 messages (and every new one) with a line for how many are left out; words stay whole. Before, it was the new words and the thread's first 70 characters, and an agent answered one thread with another's context.
- Flag `sinceLooked`: an "Added · N" pill of ids the agent added since you looked, and an `a` key (`added` shortcut) that opens its list and steps through it; the agent sees `unseen by Leo: #v3`.
- Go mode is gone: no `2` key, no go state in the bar (its switch is now comment / pointer, keys `1` and `3`; `2` does nothing), no green go pointer, and no `go` shortcut (one in a settings file is ignored). Go pins already on pages show as before ("go", the tick when done), and a comment whose text is "go" is handled by the server and agent as before.
- "Pin over controls": with it on, the pointer over the page's links, buttons and clickable cards is the pin, not their hand. The menu item shows how to do it once without the switch: (⌥ click).
- Phones: a sent comment's card slides down whole, like any sheet, and its new pin pops in with one green ring. It used to shrink and fly into the pin, which squeezed the card, and the pin was already there while it flew (its pop-in had been dropped by a later change).

- Option-click on a pin resolves its thread without opening it (again opens it again), for whoever may resolve it.

- `labit skill` prints the agent's instructions (the skill the plugin installs), and a lab's first lines point agents without the plugin to it. So an agent that is only told to run `npx @leonidstern/labit@latest` reads the skill and answers pins.
- Closed pins show on the page by default, faded and small (50% opacity, 80% size; hover or open brings them back to full), so the open ones stand out; D (or **hide done** in the ⋯ menu) still hides them, and that choice is kept per browser. This undoes 0.6.2's solid done tick for resolved pins.
- A pin whose spot is gone from the page is no longer a state of its own: it looks like a closed pin (same faded look) and says nothing about having moved. Nothing changes on disk or for the agent.
- Moved pins: a pin whose spot is gone from the page is no longer drawn on it. The ⋯ menu counts them ("moved · N"); a click opens each in turn, on the left edge, to drag onto a new spot or close. When the agent finishes one (`--done`), it closes on its own.
- Pause motion (P) is gone for now: it didn't work. A `pause` shortcut in a settings file is ignored with a warning.
- One motion system: durations (`--lab-t-quick` 120 ms, `-base` 200, `-slow` 300, `-loop`, `-hold`) and curves (`--lab-ease`, `-out`, `-in`, `-settle`, `-pop`) are tokens next to the colours, in the widget and in `lab.css`, and every transition and animation uses them; reduced motion is one rule on the tokens. See `docs/motion.md`.
- npm gets releases only: a merge to main no longer publishes `next`. A version bump still goes out as `latest`.
- Claude Code wakes for pins: the labit plugin (`hooks/wake.ts`) gives the session that last listened a new turn when pins land while it isn't listening (its wait ended, or it stopped waiting again), instead of the pins reaching nobody. It asks the lab's new `GET /_lab/pending` every 4 s while the session is idle, and wakes it once per set of pins. A wake taken back with Escape (it never started a turn) can wake it again after 15 s. Other agents keep using `wait`.
- A listener that can't lapse (Claude Code plugin, `hooks/wake.ts`): the wake no longer waits for the session to be idle. A pin left while the session is busy (a long build, no `wait` running) is submitted as its next turn (`$.prompt.submit` queues it behind the running turn), so it starts the moment that turn ends instead of the pin sitting until someone runs `wait`. A pin must be unheard on two looks (about 8 s) before it is queued while busy, so an agent about to run `wait` itself isn't woken for nothing, and a queued wake's 15 s "lost" clock starts when the busy turn ends, not before. The thread stamp does not say "queued" yet (that needs widget work).
- The wake finds the lab from any folder: besides `.lab/server.json` above the session's folder it reads the lab registry (`~/.labit/servers/<port>.json`, what `labit list` reads), where each lab now records `listener`, the id of the session whose `wait` ran last. A session whose folder is elsewhere is woken for the labs that name it. Still only that session, only on a lab that says it listened last, localhost only, at most 4 labs per look.
- The agent confirms a hand-off: `wait` (CLI and MCP) says it showed the pins (`POST /_lab/ack`). A hand-off not confirmed within 20 s (`LAB_ACK_MS`), or one the same session waits again before confirming (an MCP wait cancelled after the lab answered), goes out again whole, rules included. Before, its pins showed "being worked on" and came back after 3 minutes as one line each. A reply from that session also confirms.
- Open pages on other pages no longer fetch every comment change: the stream names the pages each change touched (`commentPages`), and a tab skips a change that isn't on its page.
- One write for a comment: who wrote it (the agent's session, or this computer / a wifi guest), what an agent's answer is, and an agent's done closing the thread are saved by the comments API in the same write. The lab used to rewrite each record after the API had saved it.
- The comments' shape (`lib/schema.mjs` VERSION) is in the stream and the widget's tag: a page reloads when the lab stores comments in a newer shape.
- `reply` and `pin` run again with the same words (the agent never saw the first answer) give back the first comment instead of posting twice. A reply after the person wrote again is a new one.
- The listening badge has three looks: a plain green rabbit while an agent is connected and listening, green with twitching ears while it works on pins, and black only when nobody listens. Black used to mean listening, grey nobody. A dropped connection (a phone waking, the laptop sleeping) keeps the last look, faded, with "reconnecting", instead of going to nobody.
- Labs & pages: ⌘K (Control-K off a Mac), or "labs & pages" in the ⋯ menu, opens a box listing every lab running on this computer and its pages, with open comments and who's listening. Type to filter, ↵ goes, ⌘↵ opens a new tab. Each lab can be **archived**: Claude's wait on it ends with "stopped from the page" (it doesn't wait again until asked) and the lab stops. With nobody listening, **get Claude listening** copies a line to paste to your agent. The ⋯ menu now opens with the lab's name and port. On a phone the box is a sheet that holds still when the keyboard comes up. A wifi guest sees this lab's pages and the other labs open to the wifi: tapping one of their pages goes through `/_lab/hop`, where this lab asks that one for a one-time link for the same name, so the phone needs no new invite. New routes: `GET /_lab/labs`, `POST /_lab/labs` (this computer, with the lab's key).
- Labs & pages, in words and about pages: each lab is a heading (its folder, which goes to its home; its port, who listens, its totals, when it was made and how long it has run are on hover), and each page reads "Title /path   5m ago": its last activity, a comment, reply or close or someone opening it, and labs and pages are ordered by it, newest first; when it was last opened (kept in `.lab/opened.json`), who commented, replies and the file's time are on hover. A guest's box lists only the keys that work for a guest, and this computer opened through its wifi address is told to use localhost for every lab and the lab keys. On a phone it is one of the widget's sheets, the comment and chat drawer: the handle, the swipe down, the dimmed page, the keyboard fit and back closing are theirs; on a computer the page dims with the widget's own `.scrim`. A phone also names the labs it can't open (not on the wifi, or on an older labit) under "on the computer only".
- A lab's home (its list of pages) speaks to a phone in phone words: hold a spot to comment, ⋯ then "labs & pages" for another lab, instead of keys. On a computer it adds ⌘K.
- CI reuse check (`npm run reuse`, `ci/reuse.mjs`): fails on a second drawer, dimmed page, swipe or keyboard fit, a new animation, a new widget module, or a long style copied into a second rule. Something genuinely new is listed in `ci/parts.json`, on purpose, in the same pull request.
- A lab no longer starts on a port another lab holds. A lab on the wifi listens on every address, and macOS still let a second lab take 127.0.0.1 on the same port, so localhost reached one lab or the other; ports in `~/.labit/servers` are skipped now.
- `labit publish <page.html | folder> [--name "topic"]` shows a page the way an Artifact is shown: it goes into your one pages lab (`pagesFolder`), which starts if it isn't running, and prints the page's link. Publishing again updates it at the same link. The skill uses it for every page that isn't part of a project's site.
- One lab per project, not one per topic: the skill has agents check `labit list` and reuse the running lab, and put pages that belong to no project (tries, demos, options) in one pages lab, a folder per topic, instead of a new folder and lab each time. Its folder is the new personal setting `pagesFolder` (default `~/lab-pages`).
- Labs & pages is one list of pages from every lab, last active first, with no lab headings: each row names its lab (its topic, or its folder) in grey beside the time. A lab is only the folder a page lives in. ⇧⌥A archives the chosen page's whole lab (press it twice); the heading buttons are gone. Opening "archived" keeps the list where it was and chooses its first row. Search also matches the grey lab label and the lab's folder; a long lab label gives way to the page title; a search with no results says "nothing matches" on a phone too.
- Labs & pages can archive a page: ⌥A on the chosen one folds it away under "archived" at the bottom, with its lab's name; ↵ still opens it and ⌥A there brings it back. The file stays; the list is the lab's `.lab/archived.json`. A whole lab still archives with its button. New `POST /_lab/labs` actions: `archive-page`, `unarchive-page` (with `page`).
- A lab can be named for its topic: `labit --name "Lab navigation"`. Labs & pages (⌘K) and the ⋯ menu show the name instead of the folder (the folder is on hover); it's kept in `.lab/name`, so later starts keep it. The skill asks agents to name the labs they start.
- ⌥W goes to the next new comment from the widget's text boxes too, where W types a letter (Shift-⌥W: the one before). Control-D still does.
- Labs & pages, archiving and dates: a lab can be **archived** (it stops and folds away under "archived · N" at the bottom; ↵ starts it again, same folder and port). Each lab is headed by its folder (~/projects/site), its port on hover. Parking was tried and taken out: a lab parked by an earlier build shows under archived too. One order: last active first (sorting was tried and taken out). Each page reads its last activity (a comment, reply or close, or someone opening it). ⌥A archives the chosen row's lab (asks twice); a separate stop listening was tried and folded into archive. The footer is one short line. On a phone: the sheet fills the space above the keyboard, a swipe down from the top of the list closes it, and it opens scrolled to the page you're on.
- Listening, per page: the lab tells pages which of them a wait hears (`heard` in the state). A page that no wait covers (another session listens with `--page` on a different one) says "no agent on this page" instead of "talking to Claude", and its comment box says "no agent listening yet". Hovering the pill says what to tell the agent to listen there. A wait that runs out keeps the pages saying listening for 45 s (`LAB_BETWEEN_MS`), so the agent's next wait doesn't flash "no agent" in between; a cancelled wait still shows it at once.
- Two sessions on one lab: when one gets its pins, the lab stays "listening" while the other's wait is open, and the ten-minute timer after a hand-over no longer turns every page away while a wait is still open. Before, one session working on its pins turned the other's pages to "no agent listening".
- `reply <id> --wait --page /x` listens on /x, as `wait --page /x` does. It used to drop the page and listen on every page instead, so a session answering on one page stopped hearing it.
- A pin between two blocks whose block above is gone (the section was deleted) no longer crashes the widget: it sits at the end of the box instead. Before, one such pin stopped the bar from drawing on its page.
- Actions are a setting (`actions` in labit.json or your settings.json): `{ "words": ["rewrite", "cut", "go"], "spot": ["go"] }` by default. Comment is always first and unlisted (the dialog opens as a comment, so its row has no comment button, and picking an action again goes back to the plain comment); list the built-in rewrite, cut and go, or your own `{ "label": "tighter", "send": "Tighter: less space" }` (`"ask": true` puts the text in the box first). Up to 5, labels up to 16 characters; slash keys follow the labels' first letters. `spot` is checked and kept for the regular box, which has no actions row yet. See docs/settings.md.
- Selected words, one comment element: the actions bar (comment, rewrite, cut, go) appears at the end of the words, with no chip first, and the box joins it once you type, click comment or press Tab or Enter.
